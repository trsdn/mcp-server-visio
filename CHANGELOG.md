# Changelog

All notable changes to VisioMcp will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- `ATTRIBUTION.md` documenting the project's provenance: the Excel -> PowerPoint -> Visio lineage, what architecture was inherited from the upstream projects by Stefan Broenner, what domain code is no longer shared, and why `LICENSE` carries a dual copyright notice. Linked from `README.md` and `FEATURES.md`
- Validated Visio-native MVP across the shared service layer, CLI, and MCP server:
  - document sessions with create/open/save/close flows
  - page list/read/create/rename/delete
  - shape list/read/add basic shapes/add text boxes/move-resize/delete
  - text get/set/find/replace/word-count
  - ShapeSheet cell value and formula read/write paths
  - stencil master enumeration and drop-to-page workflows
- Real visible-mode support so Visio can be shown live during automation
- Regenerated skill and prompt surfaces aligned to the current Visio MVP
- Updated root, CLI, MCP, extension, and installation docs to describe the current Visio-first state more truthfully
- Six Visio-native LLM integration scenarios under `llm-tests/`, covering page/shape/connector/ShapeSheet/stencil/export workflows
- `<param>` documentation for the `shape` tool's `propertyName`/`propertyValue` arguments, which were shipping to agents with empty descriptions in both generated skills

### Security

- Upgraded `Scriban` from 6.6.0 to 7.2.6, clearing one critical and four moderate NuGet advisories (GHSA-5wr9-m6jw-xx44, GHSA-6q7j-xr26-3h2c, GHSA-m2p3-hwv5-xpqw, GHSA-q6rr-fm2g-g5x8, GHSA-xw6w-9jjh-p9cr) that were failing the build through `NuGetAudit`

### Removed

- **All PowerPoint-era code from the public surface.** The repository was bootstrapped from a PowerPoint MCP server (see `ATTRIBUTION.md`), and a feature-completeness audit against the Visio COM object model found that a large part of the advertised surface still called the PowerPoint object model. Because every COM call is late-bound through `dynamic`, this code compiled cleanly and failed only at runtime, so the tools promised operations that could never work against Visio. Removed rather than quarantined:
  - 26 command domains: accessibility, animation, background, chart, comment, custom show, design, header/footer, hyperlink, image, master, media, notes, page setup, placeholder, print options, proofing, section, slide, slide import, slideshow, slide table, SmartArt, tag, transition, and VBA
  - 36 methods inside the surviving `shape` and `text` domains, including `SetFill`, `SetLine`, `SetRotation`, `Scale`, `Flip`, `CopyToSlide`, `SetActionSettings`, `Format`, `SetBullets`, `SetSpacing`, `InsertLink`, and `InsertSlideNumber`. The underlying capability remains reachable through the Visio-native `cell` tool (`FillForegnd`, `LineColor`, `Angle`); ergonomic wrappers will be rebuilt on the ShapeSheet and verified against a real Visio installation
  - the `Microsoft.Office.Interop.PowerPoint` package reference, from both `VisioMcp.Core.csproj` and `Directory.Packages.props`
  - the `isPowerPointVisible` alias field from the session-list JSON response, which duplicated `isVisioVisible`
  - the checked-in `batch-test-static.pptx` session fixture, a PowerPoint file the Visio ComInterop tests were opening. It is now generated by Visio itself on first use via the new `VisioTestFixture` helper, so the fixture always matches the installed version's format
- Five pre-commit and CI scripts that scanned hard-coded PowerPoint-era paths (`audit-core-coverage.ps1`, `check-mcp-core-implementations.ps1`, `check-cli-coverage.ps1`, `check-cli-action-coverage.ps1`, `audit-cli-actions.ps1`). They pointed at `src/VisioMcp.Core/Models/Actions/ToolActions.cs`, which has never existed in this repository, so they had been silently reporting "0 Core methods, 100% coverage" or failing outright. Actions are emitted by source generators, so the replacement reads the generated enums by reflection and cannot drift out of date
- `docs/SECURITY.md`, a stale duplicate of the root `SECURITY.md` inherited from the Excel-era upstream. It routed vulnerability reports to an upstream maintainer's personal address and still documented Power Query privacy levels. The root `SECURITY.md` (the GitHub-standard location) is now the single security policy
- Leftover `// Copyright (c) Sbroenne.` header lines from five test files, which duplicated the Torsten Mahr copyright line directly below them and were inconsistent with the other 210 source files that carry no per-file header. Upstream copyright remains recorded in `LICENSE`
- The `window` tool's `set-view` and `get-view` actions. **BREAKING.** They wrapped PowerPoint's `ViewType`/`SlideShowView`, which has no Visio counterpart. The `window` domain now exposes 23 actions covering real window geometry, zoom, and pane state
- The `eval/` harness (79 files) and `scripts/build_complex_test.py`, which generated and scored PowerPoint decks
- `docs/AGENT-CLIENT.md`, `docs/ARCHETYPE-PIPELINE.md`, and `tests/VisioMcp.Core.Tests/docs/DATA-MODEL-SETUP.md`, all describing subsystems that no longer exist (the agent client, the archetype pipeline, and the Excel-era Data Model domain)
- `.github/ISSUE_TEMPLATE/breaking-changes-issue.md`, a one-off migration plan referencing the deleted `PptSlideTool.cs`
- `ReferenceCatalogFixture` and its binary assets, plus 15 obsolete `llm-tests` files
- Three one-shot scripts with no remaining callers: `refactor-service.ps1` (hard-coded path to a different checkout), `Sync-EvalAssets.ps1` (`eval/` is gone), and `fix-void-test-assignments.ps1`
- The `CopyOfficeDllToOutput_v16`/`_v15` targets in `Directory.Build.targets`, which copied the PowerPoint PIA out of the GAC. `Directory.Build.targets` is now empty
- Ten redundant `(dynamic)` casts on `ctx.Document`/`ctx.Application`, which are already declared `dynamic`

### Fixed

- Corrected stale upstream author metadata: `mcpb/manifest.json` author name and the VS Code publisher display name in `vscode-extension/PUBLISHER-GUIDE.md` now name this project's maintainer, matching the `trsdn` publisher ID
- `vscode-extension/LICENSE` now carries the same dual copyright notice as the root `LICENSE`
- Replaced the non-existent `VisioMcpserver.dev` domain across 8 files (MCPB manifest and README, release workflow, skill build script, both skill READMEs, agent `package.json`, and the CLI tray docs link) with live GitHub URLs. Documentation links now resolve to the repository, feature links to `FEATURES.md`, installation links to `docs/INSTALLATION.md`, and the MCPB privacy policy to the existing Privacy & Security section of `mcpb/README.md`
- `check-com-leaks.ps1` excluded `PptBatch.cs`/`PptSession.cs` from its session-file exemption, filenames that do not exist here. It now exempts `VisioBatch.cs`/`VisioSession.cs`, so the session layer no longer reports a false leak
- The MCP server suggested `presentation.pptx` when rejecting a relative path; it now suggests `drawing.vsdx`
- Seven files targeted the non-existent framework `net10.0-windows`. This was silent breakage, not cosmetic: the pre-build cleanup script (`Stop-VisioMcpProcesses.ps1`) never found a running `visiocli.exe`, and the CLI smoke test (`Test-CliWorkflow.ps1`) never found a binary to test. Also affected `Test-LlmRegressionGate.ps1`, `Build-AgentSkills.ps1`, `llm-tests/cli/conftest.py`, and `docs/DEVELOPMENT.md`
- `Directory.Build.props` published the wrong repository URL (`torstenmahr/mcp-server-visio` instead of `trsdn/mcp-server-visio`) into every NuGet package
- Thirteen calls to `ctx.Document.Slides` in the ComInterop timeout and message-pump tests. Late binding meant these compiled and only failed when a real Visio document was opened; they now use `ctx.Document.Pages`
- `Build-AgentSkills.ps1` silently emitted a stale, Excel-era `cli-commands.md` on non-English Windows: it located the command list by matching `^COMMANDS:`, but a German-locale CLI prints `KOMMANDOS:`. The match is now locale-tolerant and the script fails loudly instead of writing an empty section
- `check-dynamic-casts.ps1` could not be parsed by Windows PowerShell 5.1 because the file contained non-ASCII punctuation, and it excluded three filenames (`PptBatch.cs`, `PptSession.cs`, `PptShutdownService.cs`) that do not exist here
- `check-cli-settings-usage.ps1` captured everything after the `Settings` class declaration to end-of-file, so properties of nested private classes were reported as unused user-facing settings. It now brace-matches the `Settings` body
- Two skill-quality guard tests had been inverted by an identifier rename and were asserting that the string `Visio` must *not* appear in the Visio skills. They now guard against the upstream residue they were written for
- The CLI banner still read `PPT CLI`, and the release workflow and skill builder still published under `ppt-skills`
- `OleMessageFilterTests` asserted inverted `PENDINGMSG_*` values (`WAITDEFPROCESS = 1`, `WAITNOPROCESS = 2`). `objidl.h` defines the opposite, so the test failed against a correct message filter
- The MCP and CLI tool-name guard lists still expected the deleted `hyperlink` and `master` tools and omitted `layer`, so the smoke test asserted against a surface that no longer exists
- `pre-commit.ps1` verified the MCP smoke test by matching the English summary line `Passed! ... Passed: 1`. On a German Windows the summary reads `Bestanden! ... erfolgreich: 1`, so a passing smoke test was reported as "No smoke tests passed"
- `Test-CliWorkflow.ps1` hard-failed the whole pre-commit run on machines without Visio. It now probes the `Visio.Application` ProgID and skips, since the test exists to drive real COM
- Removed `_pptApp` naming artifacts from 15 comments in the OLE message filter and resilience pipelines

### Changed

- Renamed PowerPoint-derived identifiers throughout the code base to their Visio equivalents, including `IsPowerPointVisible` -> `IsVisioVisible`, `PowerPointProcessId` -> `VisioProcessId`, `IsPowerPointProcessAlive` -> `IsVisioProcessAlive`, `PowerPointQuitTimeout` -> `VisioQuitTimeout`, and the `RequiresPowerPoint` test trait -> `RequiresVisio`. Test file extensions moved from `.pptx`/`.pptm` to `.vsdx`/`.vsdm`
- Renamed the CI repository variable `ENABLE_POWERPOINT_INTEGRATION_CI` to `ENABLE_VISIO_INTEGRATION_CI` and the self-hosted runner label from `powerpoint` to `visio`. **Both must be updated in the repository settings before integration CI will run again.**
- Renamed `skills/shared/ppt_agent_mode.md` to `visio_agent_mode.md` and the two `ppt-com-*` instruction files to `visio-com-*`, and pruned the generated skill-prompt description map down to the five skill files that actually exist
- Replaced 661 lines of per-domain copy-paste coverage tests with four reflection-driven tests that enumerate the generated action enums, plus a guard test asserting that no presentation-era action name can reappear
- Reframed feature documentation around validated Visio functionality instead of inherited PowerPoint inventory, with action counts read from the generated enums
- Updated package and extension metadata from PowerPoint language to Visio language
- Continued repository cleanup by removing misleading public PowerPoint claims from user-facing surfaces
- Renamed the `shapealign` tool's `slide_index` parameter to `page_index`. **BREAKING** for existing callers
- Renamed the `slide-design-principles` / `slide-design-review` skills to `diagram-design-principles` / `diagram-design-review`
- Removed the `FileValidationInfo.SlideCount` and `ShapeListResult.SlideIndex` aliases. **BREAKING** — use `PageCount` and `PageIndex`
- Rewrote `mcpb/README.md`, `examples/README.md`, `docs/ADR-001-NO-UNIT-TESTS.md`, `docs/CONTRIBUTING.md`, and `docs/DEVELOPMENT.md` code samples against the real API (`IVisioBatch`, `VisioSession.BeginBatch`, `ctx.Document.Pages`, `CellsU`/`FormulaU`)
- Rewrote `docs/TIMEOUT-IMPLEMENTATION-GUIDE.md`, which documented a per-call `timeout` parameter, `MaxOperationTimeout` clamping, and an async API — none of which exist. It now describes `ComInteropConstants` and the per-batch `operationTimeout`
- Rewrote all ten `.github/instructions/*.md` files and the three remaining issue templates around Visio types and idioms, and converted every `bash` fence to `powershell` (Rule 25)
- Synchronised the operation counts across `FEATURES.md`, `mcpb/README.md`, and `mcpb/BUILD.md` to the generator's actual output: **11 command domains, 101 actions, 11 MCP tools**
