# Diagram Design Principles

Use these rules to keep generated Visio pages clear, readable, and easy to maintain.

## One Purpose Per Page

Each page should communicate one coherent structure:

- one process
- one system view
- one hierarchy
- one comparison

If a page is trying to do more than one of those jobs, split it.

## Favor Readable Structure

- Keep related shapes aligned to a visible grid.
- Leave consistent spacing between sibling shapes.
- Avoid crossing connectors when a cleaner route is available.
- Place labels close to the shapes or connectors they describe.
- Reserve whitespace so the page can still be scanned quickly.

## Text Rules

- Prefer short, specific labels over long paragraphs.
- Use consistent naming across pages.
- Put the most important word first when space is tight.
- After setting text, read it back to confirm it was applied to the right shape.

## Connector Discipline

- Use connectors to show actual relationships, not decoration.
- Keep flow direction consistent on a page when possible.
- Reuse the same connector style for the same semantic meaning.
- Avoid arrow clutter around dense clusters of shapes.

## Shape Discipline

- Use stencil masters for standard diagram elements when available.
- Keep similar concepts visually consistent.
- Resize shapes to fit labels instead of truncating important text.
- Avoid unnecessary novelty shapes when simple geometry communicates better.

## Geometry Adjustments

Use ShapeSheet edits for deliberate refinement only:

- spacing and alignment corrections
- connector endpoints or routing inputs
- width, height, and position tuning
- guarded formulas where the diagram needs structural constraints

## Final Review

Before closing the file, verify:

- page names are meaningful
- important labels are readable
- shapes are not unintentionally overlapping
- connectors point to the intended targets
- the page can be understood without extra narration
